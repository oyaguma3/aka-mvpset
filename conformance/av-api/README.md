# 認証ベクターAPI の適合試験

取得先（aka-vecgen と、同じ契約を実装した他のノード）が、認証ベクターAPI の契約（[`docs/av-api-contract.md`](../../docs/av-api-contract.md)）に合っているかを確かめるコマンド `av-conformance`。契約 §14 の項目 C1〜C11 を行う。

- 試験は認証ベクターAPI だけを話す。試験用の加入者は、取得先の実装が自分の管理の手段で先に入れておく。
- 返ったベクターは、試験用の加入者の鍵で計算し直して比べる。Milenage と EAP-AKA' の鍵の導出は、取得先と同じライブラリを使うと誤りを見逃すので、このモジュールの中に自前で書いた（`milenage/`。TS 35.208 と RFC 5448 の試験ベクターで確かめてある）。
- 外部依存はない（Go の標準ライブラリだけ）。

## 項目

| # | 確かめること | 黒箱 |
|---|---|---|
| C1 | 形の誤り（400・501）。登録した IMSI と登録していない IMSI で応答が変わらないこと | 行う |
| C2 | EAP-AKA と UMTS-AKA のベクターの値（XRES、CK、IK、AUTN の MAC-A）と SQN の増加 | 行わない |
| C3 | EAP-AKA' の CK'・IK'（ネットワーク名で導出した値） | 行わない |
| C4 | ベクターの数（1〜5）と SQN の並び | 数と形だけ |
| C5 | 再同期（試験の側で作った AUTS で、SQN_MS より大きい SQN が返ること） | 行わない |
| C6 | 一般的な拒否（未登録・許可なし・Inactive・Terminated・MAC-S の合わない AUTS が同じ本文になり、SQN を進めないこと） | 未登録とクライアント B だけ |
| C7 | 同じ加入者への 50 並列の要求で SQN が重ならないこと | 行わない |
| C8 | トレースID の受け渡し | 行う |
| C9 | リクエストの知らない項目を無視すること | 行う |
| C10 | 証明書なし・登録していない証明書・TLS 1.1 以下で使えないこと | 行う |
| C11 | 応答の形（Content-Type、Cache-Control、16 進の小文字、値の長さ） | 行う |

## 準備

1. 取得先に、クライアント証明書を 2 つ登録する。
   - クライアント A: 下の表で「許可」のある加入者で払い出しを許す。ネットワーク名は `WLAN` だけを許す（`-network-name` で変えられる）。
   - クライアント B: どの加入者にも払い出しを許さない。
2. 取得先に、試験用の加入者を入れる。表は `av-conformance -fixtures` でも出せる（正本は `fixture/fixture.go`）。鍵は 3GPP TS 35.208 の試験セットで、本物の SIM の鍵ではない。

| IMSI | 鍵（TS 35.208） | AMF | 状態 | クライアント A への許可 | 使う項目 |
|---|---|---|---|---|---|
| `001010000000001` | 試験セット 1 | `8000` | active | あり | C2、C4〜C8、C11 |
| `001010000000002` | 試験セット 3 | `8000` | active | あり | C3 |
| `001010000000003` | 試験セット 4 | `8000` | inactive | あり | C6 |
| `001010000000004` | 試験セット 5 | `8000` | terminated | あり | C6 |
| `001010000000005` | 試験セット 6 | `8000` | active | なし | C6 |
| `001010000000099` | — | — | 登録しない | — | C1、C6 |

aka-vecgen には、`fixtures/aka-vecgen.sh` でクライアント A・B と試験用の加入者をまとめて入れられる（aka-vecgen の段階 2-1 の後のコマンドの形）。

```bash
go build -o av-conformance ./cmd/av-conformance
VECGEN_VALKEY_ADDR=127.0.0.1:6379 sh fixtures/aka-vecgen.sh out ./av-conformance ./aka-vecgen
```

## 実行

```bash
av-conformance -url https://<ホスト>:<ポート>/nudm-ueau/v1 -ca server.pem -cert-a out/client-a.pem -cert-b out/client-b.pem
```

- 証明書のファイルに鍵が含まれていれば、`-key-a`・`-key-b` は省ける。
- 一部の項目だけを行うときは `-cases C1,C6`。
- 試験用の加入者を入れられない外部の取得先では、鍵を使わない項目だけを行う（`-blackbox -active-imsi <クライアント A に許した Active の IMSI> -unknown-imsi <登録されていない IMSI>`）。
- すべての項目が PASS か SKIP なら終了コード 0、FAIL があれば 1、引数の誤りなどで始められなければ 2。

C2〜C7 は加入者 `001010000000001` の SQN を進める（再同期の試験で約 2^20 先に飛ばす）。何度走らせてもよい。

## このモジュールの試験

```bash
go test -race ./...
```

`suite/` の試験は、契約どおりに振る舞う偽の取得先と、わざと契約から外れた偽物（未登録に 404、Cache-Control なし、拒否で SQN を進める、CK'・IK' を別のネットワーク名で導出）を相手に、すべての項目が通ること・外れた項目が FAIL になることを確かめる。
